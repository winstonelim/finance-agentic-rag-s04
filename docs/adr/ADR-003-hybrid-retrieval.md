# ADR-003. Kiwi 형태소 BM25 + RRF + Cross-Encoder 리랭킹

- 상태: **채택**
- 날짜: 2026-10-03
- 관련: ADR-002, `src/finrag/index/bm25_ko.py`, `src/finrag/retrieval/hybrid.py`

---

## 맥락

Dense 검색은 의미가 비슷한 문서를 찾는 데 유리하지만, 상품명·회사명·시행일·조항번호·숫자처럼 **글자가 정확히 일치해야 하는 조건**에서는 정답의 순위가 낮아지는 문제가 있었다. 이를 보완하기 위해 한국어 BM25를 추가하고, Dense와 BM25의 순위를 RRF로 합친 뒤 Cross-Encoder로 최종 순서를 다시 매기는 방식을 검토했다.

검색 실패 사례 3건:

- **S13 (상품명조건형)** — 카카오뱅크 정기예금 특약상 가입대상은 누구인가요? 상품명과 문서 종류인 '카카오뱅크 정기예금 특약'이 핵심 조건이지만, Dense 검색은 의미가 비슷한 다른 예금 문서를 함께 올려 정확한 문자열 조건을 구별하지 못했다. baseline MRR 0.000에서 Hybrid MRR 0.000으로 바뀌었다.
- **S15 (메타데이터형)** — 2013년 7월 1일 시행 하나은행 여신거래기본약관(가계용) 기준으로, 기한의 이익 상실 사전 통지는 며칠 전까지였나요? 회사명과 시행일인 '하나은행', '2013년 7월 1일'이 핵심인데, Dense 검색은 내용이 유사한 다른 판본과 연도를 충분히 구별하지 못했다. baseline MRR 0.000에서 Hybrid MRR 0.000으로 바뀌었다.
- **S33 (계산형)** — iM뱅크 가계대출 1억 2천만원(약정 5%, 가산 3%)의 월이자 50만원을 2개월 연체하면 연체이자는? '1억 2천만원', '5%', '3%'처럼 숫자 조건이 핵심인 계산형 질문이지만, Dense 검색은 의미는 비슷하고 수치가 다른 대출 문서를 구별하는 데 약했다. baseline MRR 0.000에서 Hybrid MRR 1.000으로 바뀌었다.

측정된 사실:

| 무엇 | 값 | 출처 |
|---|---|---|
| 공백 BM25 → Kiwi BM25 MRR | 0.289 → 0.444 | `make bm25-compare` |
| RRF only → RRF + 리랭커 MRR | 0.515 → 0.693 | `results/hybrid_norerank.json`, `results/hybrid.json` |
| baseline → Hybrid Recall@1 | 40.0% → 62.5% | `results/baseline.json`, `results/hybrid.json` |
| 조항번호형 MRR | 0.750 → 0.833 | `results/baseline.json`, `results/hybrid.json` |

## 대안

| # | 대안 | 장점 | 단점 | 왜 안 골랐나 |
|---|---|---|---|---|
| A | Dense와 BM25 점수를 정규화해 가중합 | 두 검색의 비중을 직접 조절 가능 | 점수 범위가 달라 정규화와 가중치 튜닝이 필요 | 점수 대신 순위만 쓰는 RRF가 더 단순하고 별도 튜닝 없이 재현 가능 |
| B | Dense + BM25 + RRF만 사용 | 리랭커 비용과 지연이 없음 | Recall@1 35.0%, MRR 0.515에 그침 | 리랭커 적용 후 Recall@1 62.5%, MRR 0.693으로 상승 |
| C | Kiwi BM25 + RRF + Cross-Encoder 리랭킹 | 정확한 문자열 검색과 의미 검색을 보완하고 최종 순위를 개선 | 리랭킹 지연이 추가됨 | **← 골랐다** |

## 결정

> **Kiwi 형태소 BM25와 Dense 검색의 상위 후보를 RRF로 결합하고, 상위 10개 후보를 Cross-Encoder로 리랭킹한다.**

## 근거 지표

| 지표 | 전 | 후 | 차이 |
|---|---:|---:|---:|
| BM25 Recall@1, 공백 → Kiwi | 20.0% | 35.0% | +15.0%p |
| BM25 Recall@5, 공백 → Kiwi | 42.5% | 57.5% | +15.0%p |
| BM25 MRR, 공백 → Kiwi | 0.289 | 0.444 | +0.155 |
| Recall@1, RRF → 리랭커 | 35.0% | 62.5% | +27.5%p |
| MRR, RRF → 리랭커 | 0.515 | 0.693 | +0.178 |

측정 방법: 동일한 40개 golden question으로 BM25와 Hybrid 검색의 Recall@k·MRR을 측정하고, 후보 수 실험은 10문항으로 10개와 20개를 비교했다.  
재현 명령: `make bm25-compare && make hybrid-norerank && make hybrid && make rerank-sweep`

후보 수 실험에서는 10개와 20개 모두 Recall@1이 80.0%, Recall@5가 90.0%였다. MRR은 10개가 0.867, 20개가 0.850으로 후보를 늘려도 개선되지 않았고, 문항당 지연은 1526ms에서 2163ms로 약 41.7% 증가했다. 따라서 기본 후보 수는 10개로 정했다.

## 대가

| 잃은 것 | 얼마나 | 받아들일 만한 이유 |
|---|---|---|
| 검색 지연시간 | 평균 402ms → 1342ms, 약 3.3배 | Recall@1이 35.0% → 62.5%, MRR이 0.515 → 0.693으로 개선됨 |
| BM25 인덱싱 비용 | 공백 토크나이저보다 Kiwi 형태소 분석이 느림 | 인덱싱은 사전에 수행하며 전체 BM25 MRR이 0.289 → 0.444으로 개선됨 |

## 되돌릴 조건

- [ ] 전체 Hybrid MRR이 baseline MRR 0.553 아래로 내려가면 검색 결합 방식을 다시 검토한다.
- [ ] GPU 등 리랭커 가속 환경이 확보되면 후보 수 20 이상을 다시 측정한다.
- [ ] 문서 수가 현재의 10배 이상으로 증가하면 BM25 인덱스와 후보 수를 재측정한다.
- [ ] 리랭커를 추가해도 RRF 대비 MRR 개선 폭이 0.03 이하가 되거나 평균 검색 지연이 2초를 지속적으로 넘으면 리랭커 제거 또는 후보 수 축소를 검토한다.

되돌리는 비용: `.env`의 `RERANK_CANDIDATES` 또는 리랭커 사용 여부를 변경하고 `make hybrid`로 40문항을 다시 평가한다. BM25 방식을 바꾸는 경우 BM25 인덱스를 다시 생성해야 한다.

## 결과

Hybrid 검색 적용 후 전체 MRR은 baseline 0.5527에서 0.6932으로, Recall@1은 40.0%에서 62.5%으로 향상되었다. 조항번호형 MRR도 0.750에서 0.833으로 개선되었다. RRF 단계의 Recall@10은 82.5%였고 리랭커 적용 후에도 82.5%로 유지된 반면, Recall@1과 MRR은 크게 올랐다. 따라서 BM25와 RRF가 후보를 넓히고 Cross-Encoder가 후보의 순서를 바로잡는 구조를 채택했다.
